# Contributing Guidelines

Welcome to the DCS Year 1 Semester 2 repository! We're excited to have you as a contributor. Please follow the guidelines below to help us streamline the development process.

## Forking the Repository
1. Click the **Fork** button on the top-right corner of the repository page.
2. Clone your forked repository to your local machine:
   ```bash
   git clone https://github.com/your-username/DCSYear1Sem2.git
   ```

## Branch Naming Conventions
- Use descriptive names for your branches. For example:
  - `feature/add-new-feature`
  - `bugfix/fix-issue`
- Start branch names with either `feature/`, `bugfix/`, or `hotfix/` depending on the purpose of the branch.

## Commit Message Standards
- Write clear and concise commit messages.
- Use the imperative mood in the subject line (e.g., "Add feature" or "Fix bug").
- Include a detailed description if necessary.

## Pull Request Process
1. Push your changes to your forked repository.
2. Submit a pull request to the `main` branch of the original repository.
3. Provide a clear description of the changes and why they are being made.

## Code Review Expectations
- Be respectful and constructive in your code reviews.
- Reviewers should comment on areas for improvement as well as positive aspects of the code.
- Make sure to address feedback and make the necessary changes before merging your pull request.

Thank you for contributing! We're looking forward to your contributions!
